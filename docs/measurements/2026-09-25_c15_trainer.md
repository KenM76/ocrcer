## Cross-branch contracts (verified against unmerged branches via `git show`)

- **`charset_sha256` canonicalisation — bug found and fixed.**
  `nn15_dump.rs`'s `charset_sha256_of` computed SHA-256 over a two-field
  canonical form (`{"index":I,"cp":C}`). Reading `c15-nn-table`'s actual
  writer (`git show c15-nn-table:crates/ocrcer-build/src/emit.rs`,
  `emit::charset_array_json`) showed it serialises **four** fields per class:
  `{"index":I,"cp":C,"category":CAT,"twin":T}` (`twin` = `-1` for no case
  twin). Fixed `charset_sha256_of` to build the same four-field form,
  JSON-escaping `category` with a `json_string` helper copied verbatim from
  `ocrcer_build::ocrw::json_string`. `model_meta.json`'s `charset_sha256` in
  the fresh `nn15b` dump (`d12f9135c01911069d1fceab217f28aa6326284192487acdb51d3bf5eac4955e`)
  and `spec.json`'s copy of it now both come from this corrected function.
  Re-verify at actual merge time; this was checked by reading source on both
  branches, not by running both writers side by side in one tree.
- **Tensor file indexing — checked, no mismatch.** `c15-nn-table:crates/ocrcer-build/src/nn.rs`
  and `c15-forward:crates/ocrcer-core/src/nn.rs` both use the same convention
  `nn15_dump.rs`/`train.py` already had: `layer_index` is the position in the
  *full* ordered layer list (0..10, including non-parametric `relu`/
  `maxpool2`/`flatten`/`concat_features`), and only 0, 3, 8, 10 (the two
  convs, two denses) get `<layer_index>.<weight|bias>.f32` files. No change
  needed.

## Step 3: trainer

Environment: `D:/Dev/ExcludedPrivate/ocrcer/nnprobe/venv`, `torch
2.14.0+xpu`, device `Intel(R) Arc(TM) Pro B50 Graphics`.

**XPU exploration, 3 junk ratios, 12 epochs each, same seed (0):**

| neg_ratio | wall (XPU) | net top1 real-val | matcher top1 real-val | junk_nonpath argmax=junk | junk_nonpath low-conf-not-junk | junk_render argmax=junk | junk_render low-conf-not-junk |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 1.0 | 124.1 s | 0.9560 | 0.9199 | 0.9904 | 0.0014 | 0.9890 | 0.0013 |
| **2.0** | 187.7 s | **0.9582** | 0.9199 | 0.9893 | **0.0005** | 0.9879 | 0.0010 |
| 3.0 | 251.6 s | 0.9549 | 0.9199 | 0.9905 | 0.0011 | **0.9910** | **0.0000** |

**Chosen: neg_ratio = 2.0.** Highest real-val top-1 of the three, and the
best non-path low-confidence-not-junk rate; ratio 3.0 edges it out on the
rendered-line junk metrics specifically but loses top-1 accuracy, and ratio 1.0
loses on both. This is a guess narrowed by measurement, not a proof of
optimality -- only 3 values were tried, per the task's `2-3` instruction.

**Deterministic CPU run, neg_ratio=2.0, 12 epochs, run twice
(`--device cpu --deterministic`, `torch.use_deterministic_algorithms(True)`,
`torch.set_num_threads(1)`):**

| | run 1 | run 2 |
|---|---:|---:|
| wall time | 4313.3 s (~71.9 min) | 4290.3 s (~71.5 min) |

All 8 tensor files (`0/3/8/10 x weight/bias`) are **byte-identical**
(SHA-256 match) between the two runs -- determinism confirmed on this

| junk source | n | argmax = junk | argmax != junk but p(top charset) < 0.5 |
|---|---:|---:|---:|

network unconfident about which charset class it is, rather than
