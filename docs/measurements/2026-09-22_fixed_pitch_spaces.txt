# when classed FixedPitch, a false negative otherwise; a fragment on a
# proportional page classed FixedPitch is a false positive.

# cg=0 (column cut off):
#   mono:  TP 1431 FP 0    FN 189  precision 100.0%  recall  88.3%  F1 93.8%
#   prop:  TP 0    FP 38   FN 0    precision   0.0%  (38/2585 = 1.5% of

# cg=2.5 (column cut on):
#   mono:  TP 1801 FP 0    FN 501  precision 100.0%  recall  78.2%  F1 87.8%
#   prop:  TP 0    FP 52   FN 0    precision   0.0%  (52/3228 = 1.6%)
#   overall: precision 97.2%  recall 78.2%  F1 86.7%
#
# Reading: the detector is precise, not loose. Every mono-page false
# negative is exactly that -- a miss, never a wrong call -- and the false-
# positive rate on proportional pages is small and stable across cg settings
# (1.5% -> 1.6%). This refines the earlier "fires on roughly a third of

### Item 2: statement cg=0 regression (F1 68.278% -> 67.594%, deletions
### 292 -> 323) traced to a specific proportional-font failure mode
# Method: per-font, statement-only, cg=0, pitch on vs off (`--worst 15`),
# confusion counts parsed per font; then `--layout` and `--raw` on the
# specific fonts/pages carrying the extra deletions.
#
# Per-font result: the regression is carried ENTIRELY by proportional fonts.
# All 10 of 11 proportional families regress (deletions increase); every one
# of the 7 monospace families is flat (0 -> 0 deletions) or improves
# (roboto-mono F1 +15.980pp, inconsolata F1 +9.702pp, both via large
# insertion drops with zero deletion cost). open-sans-condensed is the one
# proportional family that does not move (32 -> 32).
#   font                  del off -> del on   (mono/prop)
#   inter                 27 -> 32  (+5)       prop
#   lato                  29 -> 33  (+4)       prop
#   liberation-sans       21 -> 25  (+4)       prop
#   pt-sans               21 -> 25  (+4)       prop
#   roboto-condensed      25 -> 29  (+4)       prop
#   noto-serif            34 -> 37  (+3)       prop
#   roboto                22 -> 25  (+3)       prop
#   stix-two-math         28 -> 30  (+2)       prop
#   liberation-serif      33 -> 34  (+1)       prop
#   noto-sans             20 -> 21  (+1)       prop
#   open-sans-condensed   32 -> 32  (+0)       prop
#   all 7 mono fonts      0 -> 0 or improving  mono
#   TOTAL (per-font sum): del 292 -> 323 (+31), matching the aggregate above.
#
# Root cause, confirmed by `--layout` on every proportional font checked
# (inter, lato, liberation-sans, roboto, noto-serif, stix-two-math, ...):
# the page title "ACCOUNT STATEMENT" (the first line of every statement
# page, all-caps) is misclassified FixedPitch and its single real word gap
# is fused. Ten concrete instances (all page 0, statement corpus, pitch on):
#   font              size  truth              got            p       d at the word gap (idx 6 of 15)   page really mono?
#   inter             10px  ACCOUNT STATEMENT  ACCOUNTSTATEMENT  10.0  13.00  (threshold 15)   no
#   inter             14px  ACCOUNT STATEMENT  ACCOUNTSTATEMENT  13.0  16.00  (threshold 20; this size/font clears it -- see note)  no
#   inter             18px  ACCOUNT STATEMENT  ACCOUNTSTATEMENT  15.0  19.00  (threshold 23; clears -- see note)  no
#   lato              10px  ACCOUNT STATEMENT  ACCOUNTSTATEMENT  10.0  10.00  (threshold 15)   no
#   lato              18px  ACCOUNT STATEMENT  ACCOUNTSTATEMENT  14.0  16.00  (threshold 21)   no
#   liberation-sans   10px  ACCOUNT STATEMENT  ACCOUNTSTATEMENT   ~10   ~13   (threshold 15)   no
#   roboto            10px  ACCOUNT STATEMENT  ACCOUNTSTATEMENT   ~10   ~13   (threshold 15)   no
#   noto-serif        10px  ACCOUNT STATEMENT  ACCOUNTSTATEMENT   ~10   ~13   (threshold 15)   no
#   stix-two-math     10px  ACCOUNT STATEMENT  ACCOUNTSTATEMENT   ~10   ~13   (threshold 15)   no
#   roboto-condensed  10px  ACCOUNT STATEMENT  ACCOUNTSTATEMENT   ~10   ~13   (threshold 15)   no
# (liberation-sans/roboto/noto-serif/stix-two-math/roboto-condensed rows use
# `~` because only the failing-threshold cases were re-verified numerically
# at 10px in this pass; the "no split" outcome and FixedPitch classification
# were confirmed directly for all ten via --layout, the exact d/p values for
# every size/font pair are in the scratch dump and follow the same pattern.)
# At inter 14px/18px the gap DOES clear the threshold (16 >= 1.5*13=19.5 is
# false actually -- 16 < 19.5, still fused; the earlier "clears" note above
# was wrong on read-through and is corrected here: all ten instances fuse).
# Mechanism: in a proportional font, an all-caps run has unusually uniform
# glyph advance widths (no lowercase ascenders/descenders/x-height mix to
# create the width variance a lowercase word normally would), so the
# within-word centre-to-centre distances (~9-11px at 10px size) and the
# real inter-word gap's centre distance (~13px at 10px size) sit close
# together. The empty-cell rule requires the gap to reach 1.5x the median
# pitch (15px at 10px size) before it counts as a word boundary; 13 < 15,
# so "ACCOUNT" and "STATEMENT" merge into "ACCOUNTSTATEMENT". This reaches
# every proportional font's title line, is a per-page-title effect (fires
# once per statement page, mono pages never carry it because they don't
# reach the FixedPitch branch), and is a page's title line, run once per
# page across the corpus, so the 10-instance sample above is not diluted --
# it is close to the entire mechanism, ANY additional deletions on other
# lines are noise around this dominant single effect (per-font deltas above
# only run +1 to +5, consistent with one recurring failure plus scattered
# single-line noise).
# Classification: (a) proportional fragment misclassified as fixed-pitch.
# Not (b) -- these are never mono pages. Not (c) -- the mechanism is fully
# explained by the empty-cell rule's fixed 1.5x cutoff applied to an
# all-caps proportional run, exactly the algorithm as specified.

### Item 3: invoice cg=2.5 pitch-on residual insertions (436 "" -> " ")
# This one took longer to pin down cleanly and the finding is narrower than
# items 1-2: most residual insertions are NOT decimal-point artifacts as a
# first pass suggested; a confirmed, reproducible over-split mechanism was
# found instead, on the numeric-column band fragments the feature exists to
# help with.
#
# False lead (recorded for the record, since it consumed real investigation
# time): scanning `--raw` GOT text for `\d\s+\.\s*\d` patterns found 121
# hits shaped like "450. 00", "3 .75", "280 . 00" -- looked like decimal-
# point splitting. Cross-checking the layout diagnostic's per-fragment `d`
# array for the specific "3.75 / 45.00" numeric fragment it was matched
# against showed a clean 1-word split (no over-split) at that exact
# stem/size, so the match was wrong: whole-page GOT text cannot be mapped
# back to individual band fragments reliably by inspection (the same " " ->
# "\n" band-serialisation confound already on record above), so this
# 121-count figure is NOT reported as attributable to the fixed-pitch rule.
#
# The reliable finding instead: `--layout`, restricted to fragments whose
# rule source is FixedPitch, shows a repeating over-split on genuinely
# monospace band fragments, confirmed on cascadia-mono and fira-code across
# every rendered size (14/18/21/28/40px) on the invoice corpus's totals row
# ("Total          875.75", column-cut band fragment 1 of 3). Concrete
# example (cascadia-mono, 18px):
#   truth (full row, before column cut): "                          Total          875.75"
#   fragment: x 28..268, 18 members, threshold 17 (FixedPitch, eta 0.000) -> 7 words
#   p = 11.000
#   d = [10.00, 32.00, 11.00, 10.00, 11.00, 10.00, 22.00, 10.00, 0.50, 9.50,
#        21.00, 22.00, 21.00, 10.00, 0.00, 21.00, 11.00]
#   page's font: cascadia-mono -- genuinely monospace, confirmed (TP by
#   item 1's ground truth).
# Same fragment shape recurs at every other size for this font and for
# fira-code (line 11/14, band fragment 1 of 3, "Total"/quantity-line rows).
# 7 words out of what is really 2 ("Total", "875.75") is a severe
# over-split, all within a fragment the classifier correctly called
# FixedPitch (it IS a mono page).
# Mechanism, read directly off `d`: the true word gap (Total -> 875.75) is
# a single wide blank run that should produce one large gap. Instead the
# `d` array shows several near-double-pitch values (22.00, 21.00, 22.00,
# 21.00) interleaved with a near-zero value (0.50 paired with 9.50, and a
# literal 0.00) inside what should be that one blank run. That pairing --
# one centre distance close to 0 immediately next to one close to 2x pitch
# -- is the signature of a spurious extra connected component sitting
# inside the blank run (a rendering artifact: anti-aliasing fringe, a stray
# speck, or a glyph broken into two touching-but-separate components by the
# binarizer) rather than of real ink. Each such extra "member" the empty-
# cell rule sees inside the blank run gets its own centre-distance pair
# evaluated against the 1.5x-pitch threshold, and because the true blank
# run is wide, several of those pairs clear 1.5x*11=16.5 independently,
# each one producing an extra word break. The classifier's own FixedPitch
# call is correct (this is unambiguously a mono page and the pitch estimate,
# p=11.000, matches the font's real pitch); the failure is that
# `centre_distances` counts component centres, and a component here does
# not correspond 1:1 to a character position -- some of the 18 "members"
# in this fragment are non-glyph artifacts inside blank space.
# Classification: (b) true mono fragment where component != character.
# Not (a) -- font and pitch estimate are both correct for a genuinely mono
# page. Not (c) -- the mechanism is fully explained by the empty-cell rule
# applied to a components list containing non-glyph member counted at
# glyph-cell positions.
# This is not confirmed as the sole source of the 436 residual invoice
# insertions -- only as one clean, reproduced, well-explained mechanism
# found among them, recurring across all 5 sizes x 2 fonts (cascadia-mono,
# fira-code) checked on the same row. A full accounting of all 436 would
# need per-fragment decoded text (not currently printed by --layout) rather
# than whole-page GOT text, which is outside a measurement-only pass; noting
# this as unfinished rather than overstating coverage.

### Escalation note
# Item 2's mechanism (all-caps proportional runs having compressed
# within-word/between-word centre-distance contrast) and item 3's mechanism
# (non-glyph components inside a real blank run defeating the empty-cell
# count) are both consequences of the fixed 1.5x-median-pitch cutoff and the
# component-count-based centre_distances as specified in ARCHITECTURE.md
# section 11 -- not implementation bugs. Both point at the same kind of fix
# (a per-fragment sanity/robustness check before trusting every component as
# a glyph position, or before trusting a fixed multiplicative threshold on a
# uniform-width run), already flagged once above for the statement
# regression. This is restated here as a second, independent line of
# evidence for the same open architecture question, for ocrcer-architect,
# not actioned in this pass.

## Amendment: cell merge + grid consistency
# Implements ARCHITECTURE.md section 11's amendment (LAST entry): (1) merge
# x-overlapping neighbouring components into one cell position before centre
# distances, for pitch estimation, the grid test, and the empty-cell split;

### Bench-tool bug found and fixed: decoded-words FIFO keyed on (x0, x1) alone
# While attributing invoice cg=2.5 insertions (next section), the new
# --layout decoded-words feature was caught pairing a "Total 875.75" row

## Task 2: rejected monospace fragments, H1 vs H2
#
# Method: diffed --layout --no-decode dumps between merge_only and both
# (merge=1 held constant across the comparison, so any fragment that flips
# from FixedPitch to something else between the two logs was rejected by
# the grid-consistency check alone, on identical cell geometry). Ten
# rejected fragments pulled (all cascadia-mono, currency/drawing content,
# 14/18px), then the failing distances traced back to which flanking cells
# produced them and whether those cells were single raw components or

# x-overlap pass over all 2524 merged cell-pairs on mono FixedPitch
# fragments at cg=0 classified each merge by y-overlap and x-containment:
#
#   vertical_stack (near-zero y-overlap: i/j dot, colon dot, comma tail --
#     expected, legitimate merges):                    1525 (60.4%)
#     overlap_px  median 6.0px (p25 4.0, p75 8.0)
#     overlap as a fraction of the narrower box: median 2.00x (these are
#       small marks fully inside their neighbours x-range by construction)
#   nested_subglyph (high y-overlap, x-overlap >=90% of the narrower box:
#     one characters ink split into two components by binarization -- a
#     currency glyphs crossbar separate from its bowl, a percent signs
#     slash vs its circles -- also expected, legitimate merges):
#                                                          987 (39.1%)
#     overlap_px  median 6.0px (p25 5.0, p75 9.0)
#     overlap as a fraction of the narrower box: median 2.50x (near-total
#       containment, as expected for a compound characters sub-strokes)
#   edge_fusion (high y-overlap, PARTIAL x-overlap: two same-row components
#     of comparable, independent extent merely touching at an edge -- the
#     literal H2 mechanism, applied to the amendments own merge step):
#                                                           12 (0.5%)
#     overlap_px  median 8.0px (min 4.0, max 9.0)
#     overlap as a fraction of the narrower box: median 0.75x (0.50-0.88x --
#       genuinely partial, unlike the other two categories)
#     All 12 are on invoice-page line 9 at 28px/40px only, across 5 of the
#     7 mono families (not cascadia-mono, fira-code, or jetbrains-mono).
#
# H2 as literally scoped -- the cell-merge step fusing two real cells
# together into a spurious ~1.5p distance -- is NOT supported at volume:
# only 12 of 2524 merges (0.5%) on mono FixedPitch fragments are genuine
# partial-overlap fusions of two independently-sized, same-row components,
# confined to two font sizes on one page family. This cannot explain a
# uniform ~25pp recall collapse across all 7 mono families at every content
# type. Consistent with Task 1: merge_only alone IMPROVES mono recall,
# which would not happen if the merge step itself were routinely fusing
# real character pairs.
#
# What Task 1 isolated to the grid-consistency check (item 2) needed its own
# mechanism, found by tracing the ten rejected fragments failing distances
# back to the cell geometry that produced them. Every one of the ten
# fragments failures traces to one or both of two patterns, usually
# co-occurring in the same failing pair:
#
#  (a) H1, as hypothesised: a single narrow, asymmetric glyph -- a decimal
#      point, a hyphen, a digit "1" -- whose ink-bbox is only 2-7px wide
#      inside an 8-11px true cell, so its centre sits off the cells
#      geometric centre. Example (cascadia-mono 14px, p=8.000,
#      tolerance=1.20):
#        d[8]=9.50  L=(106,36,113,46) width7  R=(115,36,123,46)+dot width8
#      A true single-pitch step (~8px) reads as 9.50 -- just past the
#      "wide" cutoff (9.20) -- then fails the grid check outright because
#      forced into k=2 (16) it is 6.5px off, well past tolerance. Under the
#      pre-amendment agreement-only test this single wide-but-not-really
#      outlier was absorbed into the majority vote; the new all-or-nothing
#      grid check has no such tolerance for even one exception.
#
#  (b) A variant of H2, but one pixel-pipeline stage upstream of where H2
#      placed it: two adjacent glyphs anti-aliased ink already touches
#      before cells() ever runs, so binarize+components.rs hands
#      layout/words.rs a single raw connected component spanning what
#      should be two glyph-cells -- not two separate components that
#      cells()s x-overlap merge subsequently joins. Example, same
#      fragment: d[10]=12.00, d[11]=21.00 both FAIL, flanking a single raw
#      member box (131,36,147,46), width 16px, exactly 2x the 8px pitch.
#      Splitting that one component into two 8px cells near x=139 would put
#      every neighbouring distance back on-grid; merge_only and both show
#      the identical box list here (this box is one member already, not a
#      merge product), confirming the amendments explicit merge step is
#      not what created it.
#      This ~2x-pitch single-component pattern, always immediately adjacent
#      to a narrow mark from pattern (a), recurs in 8 of the 10 dumped
#      fragments and produces the largest-magnitude residuals (4-6px past
#      tolerance, versus 1-3px for pattern (a) alone). 2-4 further FAIL rows
#      per fragment are large (~4x pitch) genuine multi-space gaps failing
#      by 2-2.5px, an accumulation of the same per-glyph asymmetry in
#      pattern (a) over a longer run rather than a distinct mechanism.
#
# Verdict: H1 is real and independently sufficient to fail the grid check on
# its own (case (a) occurs with both flanking cells at ~1x pitch, no fused
# component involved -- e.g. a 20.00-vs-2p=22 failure in currency 18px line
# 0). H2 as scoped to the amendments merge step is not supported by the
# volume data (0.5% of merges, confined to one page family and two sizes).
# But a real, pre-existing ink-fusion artifact matching H2s description --
# two neighbouring monospace glyphs anti-aliased edges touching enough to
# binarize into one connected component about 2x the pitch wide -- is
# present upstream of the amendment and is the higher-magnitude, more
# frequent contributor in this sample (8 of 10 fragments), typically paired
# with an H1-pattern narrow mark on one side. Both mechanisms pre-date this
# amendment; what the amendment changed is the tolerance for either one:
# the pre-amendment agreement check (majority vote across all distances)
# absorbed a single such outlier per line without consequence, while the
# new grid-consistency check (every wide distance must land on-grid, no
# exceptions) turns one occurrence of either pattern into a whole-line
# rejection. This reframes the escalation already on file: the fix is not
# specific to cell-merge (item 1, which this ablation shows is a net
# positive left alone) but to how zero-tolerance item 2s trigger condition
# is, given that both H1-style off-centre ink and pre-existing component
# fusion are routine, low-frequency occurrences in real monospace rendering
# that the pre-amendment test tolerated and the amendments does not.

## Grid vote
# ARCHITECTURE.md section 11, LAST entry, second amendment: "the grid check
# was all-or-nothing and cost a third of monospace recall; replaced by a
# vote over the wide distances that excuses touching pairs." Implements the
# four items: (1) cell merge kept unchanged; (2) touching-run detection --
# a Cell of width >= (2-tol)*p represents round(width/p) fused positions;
# (3) the item-2 all-or-nothing test replaced by a vote via the existing
# pitch_agreement fraction over only the UNEXCUSED wide distances (those
# not flanking a touching run) -- zero unexcused distances trivially
# passes; (4) the empty-cell split (>=1.5p) measures an excused distance
# from the touching run's nearest virtual sub-cell centre
# (Cell::edge_centre), not its full box centre, to avoid a systematic
# half-pitch bias. No new params -- pitch_agreement and pitch_tolerance
# only. pitch_grid_check now controls the vote itself: false skips it
# entirely (falls back to item-2-off, i.e. the pre-amendment agreement-only
# behaviour), not a vote that always passes.
# Code: crates/ocrcer-core/src/layout/words.rs only -- new Cell::width,
# Cell::edge_centre, private touching_runs(); pitch_estimate() and
# split_by_pitch() rewritten to take &Params and compute excusal. Two
# required unit tests added
# (a_monospace_fragment_with_one_touching_pair_stays_fixed_pitch_with_no_spurious_space,
# a_mono_fragment_with_one_off_centre_glyph_among_several_word_gaps_stays_fixed_pitch);
# all pre-existing tests in the module, including
# a_proportional_all_caps_run_is_not_fixed_pitch_and_splits_at_the_word_gap
# (the ACCOUNT STATEMENT shape), still pass unchanged. Invariants:
# forbid(unsafe_code) and zero deps outside core/alloc/std unchanged.
# wasm32-unknown-unknown builds clean. cargo test --workspace: 269 passed,

## Fitted grid
# ARCHITECTURE.md section 11, LAST entry, third amendment: "the grid vote
# failed too (monospace recall 66.6%); pairwise distances are the wrong
# statistic, replaced by a fitted grid, with a bounded fallback." Implements
# the four items: (1) virtual centres for touching runs -- a run of width w
# contributes round(w/p0).max(2) equally-spaced centres, same p0 (median
# distance) as before; (2) sequential index n_0=0, n_i = n_{i-1} +
# max(1, round(d_i/p0)), then an ordinary-least-squares fit x = x0 + n*p in
# f64 over every position in the fragment; (3) fixed-pitch iff the fragment
# has >= pitch_min_glyphs positions AND >= pitch_agreement of them land
# within pitch_tolerance*p (the FITTED p, not p0) of the fitted line; (4) a
# space wherever the sequential index advances by >= 2 across a cell
# boundary. No new params -- pitch_min_glyphs/pitch_agreement/pitch_tolerance
# only, reused for the new statistic. pitch_grid_check=0 falls back to the
# pre-vote, pre-fitted-grid median-agreement test and the plain d>=1.5p
# split (mono/prop numbers below reproduce the "merge only" ablation row,
# 94.8%/1.62% at cg=0, to the pixel).
# Code: crates/ocrcer-core/src/layout/words.rs only -- new FittedGrid struct
# and fitted_grid() (shared by classification and splitting), rewritten
# pitch_estimate() and split_by_pitch() (now branching on
# pitch_grid_check), new split_by_pitch_grid(). The second amendment's vote
# (touching_runs-based excusal used only for classification, Cell::width,
# Cell::edge_centre) is removed from the classification path entirely, not
# kept as a third disabled option -- it already failed its own gate and
# ARCHITECTURE.md does not ask for three toggled mechanisms, only two (the
# new one and "a bounded fallback"). touching_runs/Cell::edge_centre remain
# in use by the pitch_grid_check=0 splitting path (item 4 of the second
# amendment, which the fallback text does not ask to remove -- it excuses
# touching runs in the empty-cell split regardless of which classification
# test is active). Five required unit tests added or rewritten in
# layout::words::tests: an_account_statement_title_is_a_known_accepted_
# fixed_pitch_regression and a_wide_account_statement_title_is_not_rejected_
# by_the_fitted_grid_either (both below), plus pitch_grid_check=true
# coverage added to the four pre-existing fixed-pitch tests (off-centre
# glyph, touching pair, QTY empty-cell split, 112.50 stays whole), all now
# exercising both classification mechanisms explicitly. All 19 tests in the
# module pass; cargo test --workspace: 144 passed (ocrcer-core), 0 failed,
# workspace-wide 0 failed. Invariants: forbid(unsafe_code) and zero deps
# outside core/alloc/std unchanged, no unsafe added, no dependency added.
# wasm32-unknown-unknown builds clean (cargo build -p ocrcer-core --target
# wasm32-unknown-unknown). No fixture blessed.
# Binary: target/release/ocr.exe, built via
#   cargo build --release -p ocrcer-bench --features pages --bin ocr
# confirmed newer than the edited source (stat -c '%y %n': ocr.exe 20:44:48
# > words.rs 20:41:39). Model: model/out/ocrcer.ocrw, not rebuilt --
# pitch_grid_check applied at runtime via --set exactly as prior passes.
# All numbers below are READINGS from this binary against this model, not
# projections.
#
# A note on the amendment's own stated rationale before the readings: its
# text motivates item 3's threshold by "a proportional word gap of 1.3p
# displaces every later position by 0.3p and fails a large fraction" of an
# all-or-nothing/pairwise test. That framing does not carry over to a
# proper least-squares fit through all positions in the fragment: a single
# 0.3p step is one residual among many, and OLS minimises total squared
# error by distributing it across the whole line's slope and intercept
# rather than letting it displace every downstream point by the full 0.3p.
# Confirmed both abstractly (an N-position simulation with one such step)
# and against this corpus's actual ACCOUNT STATEMENT geometry: the shape
# clears the fitted-grid agreement gate with room to spare (see the per-font
# reading below), which is why this amendment's own numbers below turn out
# worse, not better, than the vote it replaces on the specific defect it
# was written to fix.
