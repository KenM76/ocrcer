of continued font growth, per rule 8.

## 3. Shortlist/pruning size (match.top_k) -- reviewed, not changed

`model/params.tsv` line 84: `match.top_k = 5` (provenance: guess).

Hole-count pruning (ARCHITECTURE.md 4.1) buckets on the class's Euler
number, a property of the 187 charset classes, not of face count -- adding
54 faces' worth of prototypes to each existing bucket does not change the
~70% elimination rate or which classes it excludes.

`top_k` gates how many *classes* survive per lattice edge into the decoder,
not how many *prototypes* are scanned. Its adequacy question is "does the
correct class's best prototype rank in the top 5 across all faces," which
is a harder bar as faces grow (more competing near-distance classes), but
the failure mode actually observed in this run (below) is not a shortlist
miss -- it is the *wrong* class winning outright with the correct class
plausibly still in or near the top 5, driven by italic prototypes changing
which class is nearest, not by the correct class falling out of contention.
Raising `top_k` would not address that; it would only pass more candidates
into a decoder stage that is already scoring the wrong class highest.

Conclusion: no change recommended to `match.top_k` from this run. If a
future, larger font addition starts showing lattice-stage (not match-stage)
losses -- the correct class absent from the shortlist entirely, as
distinct from present-but-outscored -- that would be the actual trigger to
revisit this value, and that trigger has not fired here.

The net finding: italic faces fix the targeted italic-serif failure mode
convincingly (r000583 and several sibling finfilings pages), and the
finfilings corpus as a whole improves, but the cost lands exactly where
predicted -- on upright CAD/drawing-category text across the broader
pages-cov corpus -- and that cost is large enough to fail both the overall
pages-cov CER gate and the drawing-category no-regression gate. This is a
real trade-off, not a measurement artifact: italic prototypes are winning
some matches against upright glyphs they should not be competing for.
Recommendation for a follow-up attempt: constrain italic prototypes from
competing against upright classes at match time (e.g. a style-consistency
tie-breaker within a line, per the deslant discussion already on hold in
this decision), rather than relying on distance alone once italic
prototypes are simply added to the shared pool.
