# W1 (over-split short cells): fix, measurement, gates

Branch `W1-split`. Implements `ARCHITECTURE.md` §11's W1 fix as pre-registered
2026-09-27: `docs/measurements/2026-09-26_c15_tableseg.md` found 200 of 631
classified dense-table rows whose first failure is word splitting, where a
short identifier or abbreviation run is cut into ≤3-character sub-words by a
valley-sourced split. Model build recipe and corpus per
`docs/measurements/2026-09-26_c15_measure.md`.

## Code

`crates/ocrcer-core/src/layout/words.rs`:

- `Params::short_split_x_heights: f32` (new field, doc comment carries the
  measurement below). `0.0` disables the rule (byte-for-byte prior
  behaviour) and is the control value used throughout this document.
- `SHORT_SPLIT_MEMBERS: usize = 3` (new constant) — the architecture text's
  "3 characters or fewer", read as a member count at the segmentation stage
  since no glyph has been classified yet.
- `accepted_valley_splits(line, g, rule, p) -> Vec<bool>` (new function):
  which of a line's own valley-crossing gaps survive as real splits. Only
  `ThresholdSource::Valley` is in scope. Gated to a "compact run": every word
  the raw split would produce must resolve to ≤3 members, not merely the two
  either side of one cut — otherwise an ordinary sentence's incidental short
  word ("is", "of") beside a long neighbour, each with a genuine space, would
  be wrongly merged. Once a fragment qualifies as a whole, each candidate cut
  is judged on its own gap against the floor, independently.
- `split_by_rule` (existing, shared by `split_with` and `split_band_with`)
  now threads `p` through to `accepted_valley_splits` instead of splitting on
  `g[n] > rule.threshold` directly — one implementation, per `CLAUDE.md`
  rule 4.
- This is a second, independent floor from the existing
  `Params::min_valley_x_heights`: that one rejects an entire fragment's
  valley when its narrowest called space is too narrow, discarding every
  split in the fragment along with the spurious one; this one suppresses
  only the specific cut that would strand a short piece, leaving every other
  cut in the fragment untouched.
- Three new unit tests in `words.rs`'s `mod tests`:
  `a_compact_run_valley_split_below_the_floor_is_suppressed`,
  `a_compact_run_valley_split_above_the_floor_still_splits`,
  `the_floor_is_scoped_to_a_whole_short_run_not_one_side_of_a_cut`. The third
  builds its components directly (not via the `line_of` helper, which forces
  uniform 8 px widths) so its five-member long word does not itself read as
  fixed-pitch and take a different code path — widths vary, but the six
  edge-to-edge gaps are still exactly `[1, 4, 1, 1, 1, 1]`, matching the
  first test's magnitudes.

`crates/ocrcer-core/src/params.rs` and `model/params.tsv`: added
`words.short_split_x_heights` (f32, authored, tune=yes), consistent with the
existing `NAMES`/`f32_fields`/`set_f32`/`.words()` plumbing. Built model now
reports 82 param rows (up from 81 after L1).

`crates/ocrcer-bench/src/bin/w1_gap_probe.rs` (new probe, committed
alongside, same accepted pattern as `segkind_probe.rs`): the step-1
measurement tool. Purely geometric — reconstructs `band_space_rules`/
`split_band_with`'s pre-fix output (rule disabled) across every page and
records, for every compact-run valley split, that split's own gap as a
fraction of its fragment's x-height. No model or ground truth needed, and it
never reads `finfilings`, `finfilings-val`, `pages-cov`, or any fixture.

## Criterion and its value

**`short_split_x_heights = 0.70`, authored.**

Measurement (recorded in the field's doc comment, reproduced here per the
assignment's "report the measurement"): across all 320
`finfilings-train-unseen` pages, the gap in x-height units of every
compact-run valley split (4,819 samples) against the same quantity for an
ordinary multi-word fragment's splits, where both sides are always longer
than three members (21,718 samples).

**Unlike L1's clean bimodal gap, this distribution does not separate into
two populations with an empty gap between them.** It has a steep, four-fold
jump between the 0.70–0.75 and 0.75–0.80 x-height buckets (149 to 810 of the
4,819 samples), which is where the floor is set. Below 0.70, 39% of
compact-run splits sit (1,890 of 4,819) against under 0.5% of
ordinary-fragment splits (91 of 21,718), so the floor is concentrated on the
population it targets, but it is a jump in an otherwise-noisy histogram, not
a genuinely empty gap — reported plainly rather than dressed up as L1's
kind of result.

The choice is corroborated by a second, independent line of evidence, not
merely read off the jump: 0.70 already equals this module's own
`Params::lone_gap_x_heights` — the pre-existing, independently measured
ceiling above which a gap is always a space — so this floor does not
introduce a new belief about where real spaces sit, it reuses one already
authored.

   | REWRITTEN@≥0.9 | 67 | 67 |

   ```
   PASS   REWRITTEN 1270 <= threshold 1271
   PASS   LEXICON-HARM 0 <= lexicon-threshold 0  (LEXICON-CHANGED 1, report-only, ungated)
   PASS   REWRITTEN@>=0.9 67 <= confident-threshold 67
   ```

   **PASS.** The offender lists (both the "different identifier" rewrites
   and the one report-only LEXICON-CHANGED case, `"2X45"` benign) are
   byte-identical between control and W1 — no merged-token case appears in
   either run. One fewer REWRITTEN under W1 (1270 vs 1271) is a negligible,
   marginal improvement, not a regression. Per the architecture text's own
   flag ("the identifier gate matters most here"): this corpus's short
   part/thread/revision codes are exactly the shape W1 targets, and the
   result is that nothing in it merges wrongly.

2. **`cargo test --workspace`**: all green, 0 failed (214 passed in
   `ocrcer-core`, up from 211 pre-W1 — the 3 new tests — plus the rest of
   the workspace unchanged: 91 in `ocrcer-build` including the
   TSV-vs-`Params::DEFAULT` anti-drift gate, 60 in `ocrcer-bench`, 17 in
   `ocrcer-llm`, etc.). Doc-tests 0/0 throughout. **PASS.**

3. **wasm32 check** (`cargo check --release -p ocrcer-core --target
   wasm32-unknown-unknown`): clean pass, no errors. **PASS.** Core
   invariants (`forbid(unsafe_code)`, zero deps outside core/alloc/std)
   untouched — the new pass is plain integer/float arithmetic and `Vec`s,
   no new dependency.

4. **Wall time ≤ +5%** (same 160-page cohort, recognition only, solo runs,
   timed once, no other cargo activity concurrent with either run):

   ```
   control:  1694.3s for 160 pages, 10589 ms/page
   W1:       1815.2s for 160 pages, 11345 ms/page
   ```

   Δ = **+7.14% wall-clock, +7.14% ms/page.**

   **FAIL.** Exceeds the ≤+5% gate by about 2 percentage points (roughly
   756 ms/page over the 5%-of-10589 budget of ~529 ms/page).

   Reporting this as a fail rather than rounding it into the noise, per
   `CLAUDE.md` rule 8. Root cause not isolated or profiled — that is a
   question for whoever picks this back up after adjudication, not a
   self-serve retune to dodge the gate — but one plausible mechanism, stated
   as a hypothesis and not a diagnosis: `accepted_valley_splits` itself is
   cheap (a handful of small `Vec`s, O(gaps) per fragment), so the extra
   cost is unlikely to be the suppression check running; it more plausibly
   sits downstream, where a merged compact-run cell becomes one longer word
   than before, and whatever in the segmentation lattice or decoder scales
   with word length (character-level segmentation ambiguity within a word
   that used to end at the suppressed cut) now does more work per merged
   cell. This is unconfirmed — L1's own +5.99% initial failure turned out to
   be a genuine O(bands³) algorithmic bug with a free fix; nothing of that
   shape has been found here, and if the mechanism above is right, there may
   be no free fix available, only a real tradeoff between correctness and
   speed that the architect needs to see, not one this session should
   resolve by tuning the criterion.

Per the assignment ("if anything fails, stop before val and report"), **val
was not run.** Steps 3–4 do not all pass (wall time fails), so per the
assignment's explicit stop condition this session stops here.
