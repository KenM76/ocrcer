## Verdict: the router fails the gate

On the 160 unseen pages (`finfilings-train-unseen`, stride 2), the router
(mode 3, fitted thresholds, `nn15c` weights — the fitted candidate chosen by
the brief's own rule) is **+0.075 pp end-to-end CER and +0.523 pp
line-matched CER worse than mode 0.** EPS is 0.02 pp; both moved the wrong
way, one by more than 25x tolerance. Per the brief: step 2 failed, so val,
the identifier gate, and `timing_ab` were not run. `cargo test --workspace`
and the wasm32 build were still confirmed clean before committing, since
committing broken code is never acceptable regardless of the gate outcome.

The one metric that did improve is WER (32.558% → 31.390%, -1.168 pp) — not
part of the gate, reported because losses and wins are both reported
honestly (`CLAUDE.md` rule 8). This is consistent with the confusion-table
finding below: the router cleanly fixes one specific, well-known confusion
class (`"0" -> "O"`) but appears to introduce or grow small deletion-type
errors elsewhere, netting to a worse character-level score even as
word-level correctness improves slightly.

This closes chunk 15b's classifier-3 attempt. Three attempts at using the
net (classifier 1 baseline, branch A retrain as classifier 1, now classifier
3 as a router) have now failed the same step-2 gate on the same unseen
pages. `match.classifier` remains `0` by default, unchanged.

## Step 2 (once) — router vs. mode 0, 160 unseen pages, stride 2

Model: `model/out/ocrcer.ocrw` rebuilt in the worktree with the fitted route
params and `nn15c` weights (50,095 prototypes, 54 faces, 11 tables, 5.67 MB;
params 84 rows: 13 authored, 23 measured, 13 fitted, 35 guess).

| | mode 0 (matcher only) | mode 3 (router) | delta |
|---|---|---|---|
| end-to-end CER | 19.694% | 19.769% | **+0.075 pp** |
| line-matched CER | 21.584% | 22.107% | **+0.523 pp** |
| WER | 32.558% | 31.390% | -1.168 pp |
| recall | 81.013% | 80.801% | -0.212 pp |
| precision | 77.412% | 77.209% | -0.203 pp |
| F1 | 79.171% | 78.964% | -0.207 pp |

Gate rule (unchanged since 12b/12c/prior chunk 15 measurements): at least one
of end-to-end/line-matched CER must improve by more than EPS (0.02 pp), the
other no worse than +EPS. **Both got worse. Fails outright**, not a close
call.

**Per-page concentration** (160 pages, per-page CER, mode 3 − mode 0): 98
pages improved, 43 got worse, 19 unchanged. More pages improved than
regressed, but the character-weighted aggregate still moved the wrong way —
a handful of large regressions outweigh many small gains. Worst regressions:
`filing__s7__r000629` (+5.605 pp), `filing__s5__r000364` (+5.179 pp),
`filing__s7__r000650` (+5.104 pp). Best improvements:
`filing__s2__r000615` (-5.970 pp), `filing__s2__r000809` (-4.112 pp),
`filing__s2__r000432` (-3.428 pp).

**Top substitution pairs** (aligned, end-to-end, top-20 confusion tables):
mode 0's `"0" -> "O"` (786 occurrences) and `"" -> "O"` (480) both vanish
from mode 3's top-20 entirely — the router cleans up this specific,
well-documented confusion class effectively. Set against that, several
deletion-type entries grow or newly appear in mode 3's list:
`"" -> ","` grows 512 → 598, and `"" -> "t"` (306) and `"" -> "i"` (287)
enter the top 20 where they were not prominent in mode 0. Read as an
inference from the aggregate confusion diff (no per-glyph unseen-page
relabel ground truth was collected — step 2 is run once per the brief, and
building that instrumentation was not warranted once the gate failed
outright), not a proven causal claim.

Speed note, reported as measured and not a gate criterion: both runs on this
machine ran roughly 13-18 s/page (mode 0: 14,224 ms/page in master, 12,998
ms/page in the worktree on the same model/pages; mode 3: 17,904 ms/page) —
far above the sub-second-per-page projection in `ARCHITECTURE.md` §4.1.
Consistent between master and the worktree in mode 0, so this is not a
regression introduced here; likely background CPU contention from the many
concurrent builds/fits run in this session on a shared machine, not a
measurement of the engine's steady-state per-page cost. Not chased further,
since step 2 already failed and `timing_ab` was not reached.
