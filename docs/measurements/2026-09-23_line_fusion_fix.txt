# Line fusion fix: lines.baseline_split_valley_margin

Mechanism named in docs/measurements/2026-09-23_worst_pages_round2.md,
section (b)/(c): `split_point`'s valley test used a fixed two-bin margin
around each baseline peak that does not scale with type size. At this
corpus's body size, a peak's own descenders (g p q y j) land several
pixels past its own baseline -- more than two bins -- and were counted as
valley evidence of a third line between two real ones, hiding genuine
two-line fusions from `split_baselines`'s split test. Fix: scale the
margin to `baseline_split_valley_margin * median_body` (0.0 = legacy fixed
two-bin margin, the off switch).

Diagnostic instrumentation (`OCRCER_DEBUG_SPLIT`-gated eprintln!s in
`split_baselines`/`split_point`) was used to confirm the mechanism directly
on filing__r000308's three largest fused bands and has been removed from
the shipped code; see git history for the working-tree diff this document
describes, not any remaining code.
